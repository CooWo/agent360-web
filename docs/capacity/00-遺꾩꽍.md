# Capacity Web & AI — 분석 (기획안 1 → 기존 웹에 붙이기)

근거: `docs/plans/기획안1-capacity-web-ai.md` (Nov 18, 2026) · 작성 2026-11-24

## 결론

- **새 모듈 `app/modules/capacity` 로 기존 웹(상담사 360)에 붙인다.** 로그인(IAP)·권한·감사 로그·BigQuery·Cloud Run 배포·SVG 차트·AI 패널을 그대로 재사용하므로 기획안 12주 중 "인프라·Web 골격"에 드는 시간이 대부분 빠진다.
- 핵심은 **계산 엔진(순수 Python)** 이다. 필요 FTE · 가용 FTE · 기수 흐름(교육→네스팅→현업) · 이탈 · 갭 · 채용 마감일 역산. 화면과 AI 는 이 엔진을 부르는 입구일 뿐이다 (기획안 6장).
- **가장 큰 위험은 데이터와 계산식**이다. 지금 WFM 이 쓰는 엑셀의 필요 FTE·Shrinkage 계산식을 먼저 받아 그대로 재현해야 담당자가 결과를 믿는다. 예측(결근·이탈)은 그 위에 얹는다.
- AI 는 두 단계로 간다: ① 지금 있는 데이터 에이전트(오른쪽 AI 패널)로 인사이트 질문은 바로 가능 → ② 시뮬레이션·데이터 입력·화면 변경은 Gemini **함수 호출(도구)** 로 엔진을 부르는 전용 어시스턴트가 필요 (Phase 2).

## 설계 결정 (변경 시 여기 갱신)

1. **같은 저장소·같은 앱**에 모듈로 추가 (기획안 2 결정 유지). 저장소 이름은 나중에 바꿀 수 있음.
2. **계산 단위는 주(토요일 마감)**, 화면은 주·월 둘 다. 상담사 360·WBR 과 같은 주 기준.
3. **AI 제안값과 확정값을 따로 저장** (리스크 표 2행). 시뮬레이션은 확정값으로만 계산.
4. 이탈 예측은 **팀·기수 집계만** 노출 (8장 개인정보).
5. 예측 v1 은 **규칙·통계 기반**(최근 N주 비율 × 요일·시즌 지수), v2 에서 BQML(ARIMA_PLUS·Boosted Tree) — 프로젝트에 이미 경험 있음.
6. UI 자연어 수정은 **레벨 1(설정 변경)만**, 레벨 2 는 파일럿 이후, 레벨 3 제외.
