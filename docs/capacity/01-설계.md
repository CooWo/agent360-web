# Capacity Web — 설계

원본: `docs/plans/기획안1-capacity-web-ai.md` · 분석: `00-분석.md` · 진행: `02-작업목록.md`

## 모듈 구조

```
app/modules/capacity/
  module.py          build() — 자동 등록 (order=15, 상담사 360 과 AI 질문 사이)
  screens.json       메뉴·화면·기준값 (역할별 메뉴, 경보 기준 등)
  data/              저장소: sample.py (sample_data/capacity/*.json) · bigquery.py (CAPACITY_DATASET)
  services/fte.py    FtePlanner + 계산식 전략(FORMULAS) + AssumptionRules — 순수 Python
  services/changes.py 변경 처리기 (AssumptionsChange …) — core/changes.py 의 ChangeHandler
  wiring.py          구현 조립 (ChangeService 에 저장소·변경 기록·감사 주입)
  views.py           화면별 dict 조립
  pages.py · api.py  라우터 (FastAPI import 는 여기만)
  templates/capacity/
sql/ddl/03_capacity.sql   forecast_weekly · headcount_weekly · assumptions
```

- 기준일(as_of)은 공통 백엔드(`get_backend().as_of()`)에서 받는다. 주 = 일~토, 토요일 마감일로 표시.
- 데이터셋 이름은 `.env` 의 `CAPACITY_DATASET` (기본 `capacity`). `bq_setup.ddl_sql(..., capacity=)` 로 바꿔 만들 수 있음.

## 역할

| 역할 | Capacity 메뉴 | 비고 |
|---|---|---|
| admin | 전체 | 데이터 입력 포함 |
| manager (운영 매니저) | 입력 제외 전체 | |
| wfm (WFM·BA) | 전체 | 가정 확정·데이터 입력 담당. 상담사 360 은 계정 전체 조회 |
| viewer | 대시보드·결근·기수·리포트 | 시뮬레이터·입력 없음 |
| sv | 없음 | 서비스에서 `PermissionDenied` |

화면 권한은 `screens.json` 각 화면의 `roles` 를 `services/fte.check_view()` 가 확인한다 (메뉴 숨김은 편의).

## 계산 (임시 — Q1 답을 받으면 C-05 에서 교체)

- 필요 FTE = 물량 × AHT(시간) ÷ (주당 근무시간 × 점유율) ÷ (1 − Shrinkage)
- 가용 FTE = 현업 인원 + 네스팅 인원 × 네스팅 생산성
- 갭 = 가용 − 필요, 갭 비율 = 갭 ÷ 필요. `short_warn_pct`(기본 −5%) 보다 나쁜 첫 주를 경보로 표시.

## 데이터 변경

`/capacity/input` 과 `/api/capacity/changes/...` — 미리보기 → 적용 → 되돌리기. 변경 기록은 `change_log` (sample: runtime JSON, BigQuery: MODULE_DATASET.change_log). 확장 방법은 `docs/개발가이드.md`.
