# KPI 연결 (상담사 360) — 설계

## 결정 (2026-11-25, 사용자 확인)
- 원천 = AI BA CHAT 데이터 에이전트(`v11-2026`, `agent_f682354b…`)가 쓰는 `v11-2026.Dynamic` 뷰 4개. 지표 정의는 에이전트 안내문 5장 그대로.
- 상담사별 대시보드 중요 지표(순서): **NPS → SPD → Throughput → Reopen → Time to Response → Work/Handle time**
- 상담사 목록 = 상담사 INFO 재직자(LDAP 있는 사람), 팀 = TL(LDAP), 담당 SV 이메일 = TL 의 INFO 이메일
- 갱신 = v12 BigQuery 예약 쿼리 매일 11:00 KST (전용 서비스 계정 `kpi-pipeline@v12-2027`, v11 Dynamic 읽기만)
- Ramping 인 사람도 본인 대시보드에는 지표를 보여 주고 Ramping 표시 (WBR 팀 리뷰에서는 NPS 외 제외라는 안내 문구)

## 흐름
```
v11-2026.Dynamic.final_view_case      ─┐
v11-2026.Dynamic.final_view           ─┤ sql/pipeline/kpi_refresh.sql (최근 120일 지우고 다시 넣기, 한 트랜잭션)
v11-2026.Dynamic.final_view_kpi_case  ─┤        ↓
v11-2026.Dynamic.final_view_kpi_Survey─┘  v12-2027.kpi.specialist_case_daily / specialist_time_daily (상담사×일)
                                          v12-2027.kpi.case_kpi_weekly / survey_weekly (주차×LS·섹터·테뉴어·언어, 사람 열 없음)
                                          v12-2027.kpi.refresh_log
roster.v_agent_info (INFO) ──→ kpi.v_agent (상담사 목록)  ──┐
                                                          └→ kpi.v_agent_kpi_daily (성과 제외 인원 뺌) → 앱
```
- 표에는 분자·분모 합만 둔다. 비율은 앱(`app/modules/agent360/services/kpi.py` 의 `METRICS`)에서 SUM/SUM.
- 목표값(SPD·Throughput·Reopen·TTR·Work time)은 `final_view` 의 섹터·테뉴어별 목표 열을 같이 가져와 카드·차트 기준선에 쓴다.
- AQS·Resolution·Expense 는 사람 열이 없어 주차×그룹 표로만 쌓는다 (팀 화면에서 쓸 예정).

## 명령
```powershell
python scripts/bq_setup.py ddl --project v12-2027                     # kpi 데이터세트·표·뷰
python scripts/bq_setup.py kpi-refresh --project v12-2027 --days 400  # 처음 한 번: 올해 전체
python scripts/deploy.py kpi-pipeline --project v12-2027              # 예약 쿼리 + 전용 계정 권한
```

## 확인 필요
- SV(TL) 계정의 앱 역할: `user_roles.teams` 에 TL LDAP 을 넣어야 자기 팀만 보인다 (`bq_setup.py user --role sv --teams ub_xxx`).
- 근태·QA·교육·인센티브·신호는 아직 샘플 데이터 → 실제 원천 연결은 다음 작업.
