## Capacity Web & AI 구축 기획안

Nov 18, 2026 · @Coo · 글로벌운영 1팀 (에어비엔비) 박훈 · 이상욱

### 1. 개요

Capacity Web은 WFM·FTE를 관리하는 유베이스 자체 웹 툴로, 결근·이탈을 예측하고 신규 TO의 교육부터 네스팅까지 포케스트와 TO 할당 시뮬레이션을 한 곳에서 돌리는 환경입니다. 인력 산정과 TO 결정은 담당자의 판단(주관)으로 하고, AI는 데이터 근거·인사이트·시뮬레이션 보조로 그 판단을 서포트하는 것이 본 기획의 핵심입니다. 사용자는 자연어로 물어보고, 입력하고, 화면까지 바꿀 수 있습니다.

- 배경: 사이트별 인력 계획이 담당자 경험에 의존해, 결근·이탈 변동과 신규 입사자 투입 시점을 미리 반영하기에 부족한 부분이 있었습니다.

- 목적: 기존 데이터를 활용해 필요 인력을 예측하고, AI가 인사이트 도출과 시뮬레이션을 돕도록 해 의사결정 속도와 정확도를 높입니다.

- 범위: 운영 매니저, WFM 담당, BA, 채용·교육 담당이 쓰는 사내 웹 툴. 파일럿은 에어비엔비 계정에서 시작하고 타 계정으로 확대합니다.

### 2. 현황 및 문제점

### 4. Capacity Web 핵심 기능

Capacity Web은 신규 TO가 교육·네스팅을 거쳐 가용 FTE가 되기까지의 흐름과 그 사이의 손실을 예측해, 필요 FTE 대비 갭을 보여주고, 담당자가 TO를 결정하도록 돕습니다.

인력 흐름 · 채용에서 가용 FTE까지, 예측 대상 3곳

매 단계의 손실은 AI가 과거 데이터로 참고값을 제시하고 담당자가 조정합니다. 확정한 가정으로 계산한 갭을 보고 담당자가 TO를 할당합니다.

설계 원칙

- 판단은 사용자, AI는 서포트: 결근·이탈률, 교육·네스팅 기간, TO 같은 가정과 최종 숫자는 담당자가 정하고 조정합니다. AI는 과거 데이터 기반 참고값·근거·리스크를 제시하고, 계산은 담당자가 정한 가정으로 시뮬레이터가 수행합니다.

- 쓰기는 확인 후 저장: 데이터 입력과 UI 변경은 미리보기를 보여주고 사용자가 승인해야 반영되며, 변경 이력과 되돌리기를 제공합니다.

- 권한을 따른다: AI는 사용자가 볼 수 있는 계정·팀 데이터만 조회하고 수정합니다.

- UI 변경은 정해진 부품 안에서: 코드를 새로 짜지 않고, 미리 만든 위젯·차트·필터의 배치와 설정만 바꿔 안정성을 지킵니다.

### 6. 시스템 구조

Web UI, AI 어시스턴트, 계산 엔진, 데이터의 4계층으로 나누고, AI는 계산 엔진을 도구로 호출해 사용자의 판단을 돕는 방식으로 붙입니다.

시스템 구조 · 4개 계층

AI가 없어도 사용자는 화면에서 직접 조회·시뮬레이션을 할 수 있으며, AI는 같은 기능을 자연어로 열어주는 입구입니다.

### 7. 사용 시나리오

대표 시나리오는 분기 인력 계획 수립, 월중 이상 징후 대응, 신규 기수 등록의 세 가지입니다.

A. 분기 인력 계획 수립 (운영 매니저)

- 1분기 물량 포케스트 기준으로 필요한 FTE와 채용 일정을 보여줘 라고 입력합니다.

- AI가 과거 데이터 기반 결근·이탈 참고값을 제시하고, 담당자가 현장 상황을 반영해 가정을 조정하면 월별 FTE 갭과 채용 마감일이 계산됩니다.

- 보수적·기본·낙관적 시나리오 3개를 비교하고, 선택한 안을 TO 계획으로 저장합니다.

- QBR·클라이언트 보고용 요약을 생성합니다.

B. 월중 이상 징후 대응 (WFM 담당)

- 대시보드에 이번 주 결근율 경보가 뜨면, 왜 올랐어? 라고 묻습니다.

- AI가 팀·요일·시프트별로 쪼개 기여도가 큰 구간을 설명합니다.

- 추가 근무·교육 일정 조정 등 대응안별 SL 영향을 시뮬레이션합니다.

C. 신규 기수 등록 (교육 담당)

- 교육 입과 명단을 붙여넣고 등록해 달라고 입력합니다.

- AI가 입력 폼을 채운 미리보기를 보여주고, 담당자가 확인해 저장합니다.

- 등록 즉시 네스팅 종료 예상일과 가용 FTE 반영 시점이 포케스트에 업데이트됩니다.

### 8. 데이터·보안·권한 관리

인사·근태 데이터는 민감도가 높아, 리포트와 AI는 집계 데이터 중심으로 쓰고 개인 단위 조회는 권한자로 제한합니다.

### 9. 추진 일정

착수 승인 후 12주(3개월) 일정으로, 기존 데이터 파이프라인을 연결하고 Web과 예측 모델을 세운 뒤 AI를 얹어 파일럿을 진행합니다.

단계별 로드맵 · 4단계, 게이트 3개

UI 맞춤 변경은 핵심 기능이 안정된 뒤에 붙이는 선택 범위이며, 주차별 일정은 착수일과 개발 인력 확정 후 날짜로 바꿉니다.

### 10. 비용 산정
