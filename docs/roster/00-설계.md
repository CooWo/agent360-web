# 팀 구성(OPS TL) — 설계

원천 시트: `Airbnb Standard INFO TABLE` 파일의 `OPS TL`(TL별 보드), `OPS RAW`(보드를 행으로 푼 것), **`INFO 자동화 시트`(기본정보 기준 표)**.

## 사용자 결정 (2026-11-25)

1. **TL 한 명이 담당해 한 번에 업데이트** → 한 사람이 보드 전체를 한 번에 고치는 작업 공간 필요. 중간 저장 후 이어서 작업.
2. **날짜 규칙 없음** → 신규·퇴사 일자는 사람마다 다름. 주 단위 같은 날짜 로직을 두지 않는다.
   - 보드는 "지금 상태" 하나. 적용할 때마다 **버전**(적용 시각·적용자)이 쌓인다 → 과거 구성은 버전으로 본다.
   - 사람별 일자가 필요하면 행의 `반영일` 칸(선택)에 적는다. 계산에는 쓰지 않는다.
3. **사번이 없을 수 있음** → 임시 키(예: `트레이닝1`, 이름). 화면에 "임시" 표시. 나중에 사번을 넣으면 연결.
4. **기본정보 기준 = `INFO 자동화 시트` 탭** (2026-11-25 정정, 처음에 Standard INFO TABLE 로 잘못 잡았음).
   - 이 탭은 다른 파일(`1WlX447B…`)의 같은 이름 탭을 IMPORTRANGE 로 가져온 것 → **진짜 원천은 그 파일**.
   - 1행에 열마다 입력 담당: **OPS 입력**(사번·한글명·Name·Email·Airbnb ID·Batch·Shift Type·Location·Type·Tier·LDAP·FTE·온보딩·R2 온보딩·근속 인센티브), **WFM 입력**(Universal·Universal 전 Tier), **BA용**(Tenure·TL·입사일(UHR)·재직정보·퇴사 Tenure·R2 기준 Tenure·비고).
   - TL 은 LDAP 로 들어 있고, 정해지는 순서: 팀장 수정(Amb.사번·Amb.TL, Manual) → OPS 시트 자동반영(Date·Leader·Shift·사번… = OPS RAW) → 이전 데이터(퇴사자 반영용).
   - 퇴사 판단은 `재직정보 = 퇴직자`. 열 정의는 `app/modules/roster/services/info.py`.

## 흐름

```
작업 공간(초안)  ──붙여넣기/직접 수정/행 추가·삭제──▶  중간 저장(내 초안)
      │
      └─ 미리보기: 신규 · 이동 · 정보 수정 · 빠짐 + 경고(사번 없음·퇴사자·INFO에 없음·새 TL)
             │
             └─ 적용 → 새 버전 (감사 로그) ──▶ 되돌리기(가장 최근 것)
```

- 미리보기·적용·되돌리기는 `core/changes.py` 공통 틀 (`roster.board` 처리기).
- 붙여넣기: 시트 OPS TL 을 통째로(TL 이름 줄 + `Shift·사번·이름·Name·Display name` 머리글 반복) 또는 한 TL 블록만 복사해 붙여도 읽는다.
- 이름 칸이 비면 사번으로 INFO 에서 채운다.
- 한 사람이 두 TL 에 있으면 오류 (적용 불가). 퇴사자·INFO 에 없음·임시 키는 경고 (적용 가능).
- 새 TL 이 생기면 감사 로그 `roster_new_tl` (BA 알림 연결 지점 — 슬랙 등은 AuditSink 로 추가).

## 저장 (sample · BigQuery)

| 표 (`ROSTER_DATASET`, 기본 `roster`) | 내용 |
|---|---|
| `info_raw` | 시트에서 받은 그대로. 불러올 때마다 `load_id` 묶음으로 **쌓임** (3년 보관) |
| `mart_agent_info` | 정리된 지금 상태, 사번당 한 줄 (불러올 때마다 통째로 바뀜). 웹 '상담사 INFO' 가 읽음 |
| `info_loads` | 불러오기 기록 (읽은 행·마트 행·사번 없음·중복·확인 필요 칸) |
| `board_versions` | 적용할 때마다 보드 전체 JSON 한 줄 (version_id, saved_at, saved_by, doc) |
| `board_drafts` | 사용자별 작업 중 초안 (email, saved_at, doc) |

BI·Tableau 용 "지금 보드" 행 표는 `board_versions` 최신 doc 을 펼치는 뷰로 만든다 (OPS RAW 대체).

## TL별 명단 = 원본 시트 '팀구성-New' (2026-11-25)

- 원천을 `OPS TL` → 원본 INFO 파일의 **`팀구성-New`** 탭으로 바꿈 (`info/screens.json` 의 `team_sheet`·`team_tab`). 불러오기는 그대로 INFO 화면 '시트에서 불러오기'.
- 시트 모양: 날짜 줄 → TL 줄 → `Shift·사번·이름·Name·Display name` → 명단 → (육아휴가·출산휴가·무급휴직 등 쉬는 사람) → 인원·`Ratio` 줄. 날짜 묶음을 위로 쌓음 → **맨 위 묶음만** 읽고 쓴다.
- 화면 `/roster`(TL별 명단)는 `roster.team_roster` 를 시트와 같은 모양(TL 블록이 옆으로)으로 보여 준다. 예전 `roster.board`·'명단 고치기'는 메뉴에서 뺌.
- 웹 수정: 칸 고치기 → 미리보기 또는 바로 저장 → 되돌리기 (`roster.team` 변경, `services/team_edit.py`).
  - 저장 = team_roster 통째로 바꾸기(source=web) + **원본 시트 맨 위 묶음의 바뀐 TL 블록 칸을 그 자리에서 고쳐 씀** (values.batchUpdate, 명단 열만, 서식·쉬는 사람·Ratio 줄은 안 건드림).
  - 쓰기 전 확인: 시트의 그 TL 명단 = 웹의 고치기 전 명단 (다르면 멈춤 → 먼저 불러오기), 명단 칸 줄 수 안에 들어감, TL 블록이 시트에 있음. 하나라도 어긋나면 웹도 저장 안 함.
  - 시트 권한이 없으면 웹만 저장하고 '시트 반영 실패' → 공유 뒤 '시트에 다시 쓰기'.
  - TL 안 줄 순서를 지키려고 `team_roster.row_order` 열 추가 (ALTER ADD COLUMN).
- 쉬는 사람 구역·새 TL 블록 만들기는 시트에서 한다 (웹은 지금 명단 칸만).

## 근태 = 원본 시트 'Schedule KR' (2026-11-26)

- 원천: 원본 INFO 파일의 **`Schedule KR`** 탭 (행 = 상담사(A열 사번), 1행 = 날짜, 칸 = 그날 근태). WFM 이 Log·Log NOT·Log BOT 탭에서 체크하면 스크립트가 이 탭 칸을 고친다 → 이 탭이 최종본.
- 저장: `common.fact_attendance` (상담사 360 근태 칸·Capacity 결근이 같이 씀). 칸 글(`detail`)·배경색(`bg`)도 그대로 저장, `source = schedule_kr`.
- 판정 (`roster/services/attendance.py`, 2026-10-01~11-26 실제 9,137칸으로 검산 — 모르는 값 'NUbase' 7칸뿐):

  | 칸 | 상태 |
  |---|---|
  | 근무시간 `09:00~18:00` (NOT·BOT 표기 포함), 배경 `#ff9900` 또는 글에 Late | 지각 |
  | 근무시간, 배경 `#f9cb9c` 또는 Early left | 조퇴 |
  | 근무시간 (그 밖 배경, NOT 표기 포함) | 정상 |
  | Absent · Planned Absences | 결근 |
  | Approved AL · Approved AL* | 연차 |
  | …휴가 · 태아건강검진 | 휴가 |
  | …휴직 · Military | 휴직 |
  | Sat off · PH | 휴무 |
  | Training · Refresher Training | 교육 |
  | `BOT` 이 적힌 칸 (시간 없이 BOT, `12:00~21:00 (BOT 60mins)` 등) — 지각·조퇴 색이 먼저 | 연장근로 |
  | Resignation · Move to … · End of Contract 등 | 저장 안 함 (인사 표시) |
  | 그 밖 (NUbase · Blending 등) | 기타 (글 그대로) — 사용자 확인 2026-11-26 |

- 불러오기 (`services/attendance_sync.py`): 시트 호출 3번(1행 날짜, A열, 기간 열만 값+배경색 — 필요한 필드만) → 기간 안 저장분과 비교 → **바뀐 칸만 MERGE**. 바뀐 것이 없으면 쓰기 없음.
  - 기간: 지난달 1일 ~ 오늘(한국). 월말 인센티브 정리 때 고친 칸도 다시 맞춤. 앞으로 날짜(계획)는 넣지 않음.
  - 안전장치: 읽다 실패하면 아무것도 안 씀. 지울 칸이 기간 안 저장분의 20%(최소 50) 넘으면 멈춤(강제 저장만). 시트에서 빠진 사람(다른 탭으로 옮김)의 기록은 지우지 않음. 같은 사번 두 줄이면 위 줄.
  - 기록: `roster.attendance_loads` (언제·누가·바뀐 칸·뺀 칸·상태별 칸 수·모르는 값).
- 실행: Cloud Run 작업 `agent360-attendance` + Cloud Scheduler 1시간마다(매시 10분) — 웹 서버와 따로 돈다 (`python scripts/deploy.py attendance-job`). 상담사 INFO 화면 '근태 불러오기'에서 미리보기·지금 반영도 가능.
- 확인 필요: Planned Absences 를 결근으로 볼지(사전 신고 결근?), Approved AL* 의 뜻(반차·대체휴가?), Training 을 근무로 셀지. (NUbase·Blending = 기타, BOT = 연장근로 확정)
