# 팀 구성(OPS TL) — 설계

원천 시트: `Airbnb Standard INFO TABLE` 의 `OPS TL`(TL별 보드), `OPS RAW`(보드를 행으로 푼 것), `Standard INFO TABLE`(기본정보).

## 사용자 결정 (2026-11-25)

1. **TL 한 명이 담당해 한 번에 업데이트** → 한 사람이 보드 전체를 한 번에 고치는 작업 공간 필요. 중간 저장 후 이어서 작업.
2. **날짜 규칙 없음** → 신규·퇴사 일자는 사람마다 다름. 주 단위 같은 날짜 로직을 두지 않는다.
   - 보드는 "지금 상태" 하나. 적용할 때마다 **버전**(적용 시각·적용자)이 쌓인다 → 과거 구성은 버전으로 본다.
   - 사람별 일자가 필요하면 행의 `반영일` 칸(선택)에 적는다. 계산에는 쓰지 않는다.
3. **사번이 없을 수 있음** → 임시 키(예: `트레이닝1`, 이름). 화면에 "임시" 표시. 나중에 사번을 넣으면 연결.
4. **기본정보 원천 = `Standard INFO TABLE` 탭** (UBASE ID·Airbnb ID·이름·E-Name·LDAP·입사일·직무·Market·퇴사일 …).

## 흐름

```
작업 공간(초안)  ──붙여넣기/직접 수정/행 추가·삭제──▶  중간 저장(내 초안)
      │
      └─ 미리보기: 신규 · 이동 · 정보 수정 · 빠짐 + 경고(사번 없음·퇴사자·INFO에 없음·새 TL)
             │
             └─ 적용 → 새 버전 (감사 로그) ──▶ 되돌리기(가장 최근 것)
```

- 미리보기·적용·되돌리기는 `core/changes.py` 공통 틀 (`roster.board` 처리기).
- 붙여넣기: 시트 OPS TL 을 통째로(TL 이름 줄 + `Shift·사번·이름·Name·Display name` 머리글 반복) 또는 한 TL 블록만 복사해 붙여도 읽는다.
- 이름 칸이 비면 사번으로 INFO 에서 채운다.
- 한 사람이 두 TL 에 있으면 오류 (적용 불가). 퇴사자·INFO 에 없음·임시 키는 경고 (적용 가능).
- 새 TL 이 생기면 감사 로그 `roster_new_tl` (BA 알림 연결 지점 — 슬랙 등은 AuditSink 로 추가).

## 저장 (sample · BigQuery)

| 표 (`ROSTER_DATASET`, 기본 `roster`) | 내용 |
|---|---|
| `agent_info` | Standard INFO TABLE 사본 (사번 키). 시트 → BigQuery 동기화는 다음 작업 |
| `board_versions` | 적용할 때마다 보드 전체 JSON 한 줄 (version_id, saved_at, saved_by, doc) |
| `board_drafts` | 사용자별 작업 중 초안 (email, saved_at, doc) |

BI·Tableau 용 "지금 보드" 행 표는 `board_versions` 최신 doc 을 펼치는 뷰로 만든다 (OPS RAW 대체).
