# 개발 가이드 — 구조와 확장 방법 (SOLID)

새 기능은 **기존 코드를 고치지 않고 클래스를 하나 만들어 등록**하는 방식으로 붙인다.
층 구분은 `CLAUDE.md` 의 표(데이터 · 서비스 · 뷰 · 라우터 · 템플릿 · 설정)를 따른다.

## 원칙이 코드에 어떻게 들어가 있나

| 원칙 | 적용 위치 |
|---|---|
| **S** 단일 책임 | 데이터(읽기·쓰기) / 서비스(규칙·권한·감사) / 뷰(화면 dict) / 라우터(HTTP) 분리. 감사는 `Auditor`, 변경 흐름은 `ChangeService`, 계산은 `FtePlanner` 가 각자 맡음 |
| **O** 개방-폐쇄 | `core/registry.py` 의 `Registry` 로 등록: 데이터 백엔드(`BACKENDS`), Capacity 저장소(`STORES`), 계산식(`FORMULAS`), 변경 처리기(`handlers()`), 업로드 형식(`PARSERS`), 변경 기록 저장소(`CHANGE_LOGS`), 역할(`POLICIES`) |
| **L** 리스코프 치환 | sample·bigquery 구현은 같은 인터페이스를 지키고 같은 테스트를 통과 (BigQuery 는 가짜 클라이언트로 SQL 매개변수 확인) |
| **I** 인터페이스 분리 | `core/data/base.py`: `AgentDirectory`, `CoachingStore`, `SignalStore`, `AuditStore` … / Capacity: `ForecastSource`, `HeadcountSource`, `AssumptionStore` |
| **D** 의존성 역전 | 서비스는 구현이 아니라 인터페이스를 생성자로 받음 (`CoachingService(agents, store, auditor)`). 조립은 `wiring.py`·`get_*()` 한 곳에서 |

예전 함수 호출(`coaching_svc.create(backend, user, form)`)은 클래스에 넘겨주는 얇은 함수로 남겨 두었다.

## 확장 방법

### 웹에서 데이터 고치기·파일 올리기 (미리보기 → 적용 → 되돌리기)

1. 모듈의 `services/changes.py` 에 `ChangeHandler` 하위 클래스를 만든다.
   - `kind`(예: `capacity.forecast`), `title`, `permission`(예: `capacity.edit`)
   - `preview(user, payload)` → `(요약, [{"key","field","label","before","after"}])`, 잘못된 값은 `InvalidInput`
   - `apply(user, change)` → 저장하고 되돌리기용 데이터 반환
   - `revert(user, change)` → `change.undo` 로 원래대로
2. `handlers()` 에 등록한다. 끝 — API `/api/capacity/changes/{kind}/preview` · `/approve` · `/discard` · `/undo` 와 감사 로그, 변경 이력이 그대로 붙는다.
3. 파일 업로드는 `core/uploads.parse_upload()` 로 행을 만든 뒤 같은 `preview` 에 넘긴다. 새 형식(xlsx 등)은 `TableParser` 를 만들어 `PARSERS.register(".xlsx", ...)`.

`ChangeService` 가 지키는 규칙: 미리보기는 저장하지 않음 · 승인 때 다시 계산해서 그 사이 데이터가 바뀌었으면 막음 · 되돌리기는 같은 종류에서 가장 최근 적용분만 · 모든 단계 감사 로그.

### 역할·권한

- 새 역할: `POLICIES.register(RolePolicy("ba_lead", "BA 리드", all_teams=True, grants=frozenset({...})))`
- 새 기능 권한: 역할의 `grants` 에 이름을 넣고 서비스에서 `user.can("이름")` 으로 확인. 변경 처리기는 `permission` 으로 자동 확인.
- 화면 단위 접근은 `screens.json` 의 `roles` (설정으로 조정).

### 데이터 원천

- 새 백엔드: 인터페이스를 구현한 클래스 + `BACKENDS.register("이름", factory)`. `.env` 의 `DATA_BACKEND` 로 선택.
- 새 조회: 알맞은 작은 인터페이스에 메서드를 더하고 **sample·bigquery 둘 다** 구현, SQL 은 `@매개변수` 만.

### 계산식

- `RequiredFteFormula` 를 구현하고 `FORMULAS.register("wfm_excel", ...)` → `screens.json` 의 `home.formula` 만 바꾼다.

### 감사 로그 받는 곳

- `AuditSink`(`write(event)`) 를 만들어 `Auditor([...])` 에 넘긴다. 하나가 실패해도 나머지는 기록된다.
